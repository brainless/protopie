# MVP local preview guide

## Requirements and startup

Install Rust and Node.js `^20.19.0 || >=22.12.0` with npm available on `PATH`. This range matches the locked Vite 8.3.2 and Solid Vite plugin in `reference/package-lock.json`. The server reports the detected Node and npm paths and versions in the GUI and through `GET /preview/runtime`. A new project's first Launch runs `npm ci` from its copied lockfile; later launches reuse the install while both package files match. Node and npm are not installed by Protopie.

On macOS, run `./run.sh` from the repository root. It builds the server and GUI, starts the desktop window, and starts the local server as a child. For API work without the GUI, run `cargo run -p protopie-server -- --addr 127.0.0.1:3000` from the repository root. The server prints its bound address; its default address is an ephemeral loopback port. The server's `GET /projects` lists the local `.projects` folder. `POST /projects` can create projects in a specified base path.

## Edit and preview

1. In the entry view, choose **New Project**, name it, and create it; or choose a supported project and press **Continue**. Older folders without the template model or required source regions show why they are unavailable. Project creation copies `reference/` without `node_modules`.
2. Press **Launch**. Wait for dependency preparation and Vite startup, then use the browser window that opens. **Open in browser** opens the running URL again. **Stop** ends the preview; **Restart** stops and launches it again. The collapsible log tail shows npm and Vite output. You can edit while preview is stopped.
3. Enter a command or click an example to fill the input. A question-only step first shows **Continue** or **Discard**; Continue saves the question so its answer options become active. Answering may show another Continue step. When a file diff is ready, press **Apply changes** to write it, or **Discard**. The browser reloads through Vite after Apply. A changed project revision or different plan produces a conflict instead of applying a stale preview.

Examples for a fresh project: `Need a top navigation`, `Add a Doctors page`, and `Add a form below hero` (then answer its fields and submit label questions). After adding a form, `Give the form below hero more padding` changes its style. After adding a Doctors page, `Share the selected doctor across pages` asks for type, value, destination and completion before preview and Apply. For navigation, add a labelled item such as `Add Contact Us` after creating top navigation; choose a new page, an existing page or section, an external URL, or leave it unlinked. A parser accepted command can still require a suitable project state.

## Scope and release checks

This MVP supports one active local project preview at a time. Switching projects stops the old preview. Preview uses a loopback Vite server and the system browser; there is no embedded browser, deployment, remote access, auto Apply, or persistent undo. Forms generated by example commands have no submission service. A hard killed Protopie server cannot guarantee cleanup of an already started child process; normal Stop and server shutdown terminate the process group and reap the child. A new launch selects a port and waits for Vite's own ready line plus a successful HTTP response before reporting its URL.

Run `cargo test --workspace` for Rust tests. The Node gate in `.github/workflows/ci.yml` pins Node 22.12.0, runs `npm ci` in `reference/`, generated project builds, the real first install preview test, and the server HTTP conversation test. Locally, the same Node checks can be run with:

```sh
cd reference && npm ci
cd ..
cargo test -p protopie-ui-agent --test generated_build -- --ignored --nocapture
cargo test -p protopie-server preview::tests::real_first_install_serves_and_reaps -- --ignored --exact --nocapture
cargo test -p protopie-server tests::real_http_conversation_serves_generated_modules_and_reaps -- --ignored --exact --nocapture
```

The HTTP test checks Vite's entry HTML and transformed modules. The page route itself serves SPA fallback HTML, so DOM and navigation must be checked in a browser. Use the [multi-file Apply and reload runbook](mvp-live-reload-runbook.md) for route and context trials, Vite event capture, overlays, navigation history, and timing. The [Epic 003 investigation log](../epics/003-mvp-live-preview-integration.md#investigation-log) records the current manual browser follow-ups and measured results.
